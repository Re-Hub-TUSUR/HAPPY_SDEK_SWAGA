# CDEK: AI-инструмент для оценки выгорания сотрудников

Этот репозиторий содержит прототип AI-инструмента для хакатона от компании СДЭК. Приложение предназначено для ранней диагностики профессионального выгорания сотрудников, предоставления персональных рекомендаций и визуализации метрик в дашборде.

## 🤖 Технологический стек

-   **Frontend:** React, TypeScript
-   **Backend:** Python, Flask, SQLAlchemy
-   **База данных:** PostgreSQL
-   **Оркестрация:** Docker, Docker Compose

## 🚀 Запуск проекта (в режиме разработки)

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Breadstickhemmo/HAPPY_SDEK_SWAGA.git
    cd HAPPY_SDEK_SWAGA
    ```

2.  **Создайте файл с переменными окружения:**
    В корневой папке проекта создайте файл `.env`. Скопируйте в него содержимое ниже.
    ```env
    # Конфигурация PostgreSQL
    DB_USER=sdek_user
    DB_PASSWORD=supersecret_password_123
    DB_NAME=sdek_hackathon_db
    DB_PORT=5432

    # Секретный ключ для подписи JWT-токенов
    # Можно сгенерировать любой сложной строкой, например, с помощью команды:
    # openssl rand -hex 32
    JWT_SECRET_KEY=your_super_secret_and_long_jwt_key_here
    ```
    > **Важно:** Файл `.env` добавлен в `.gitignore` и не должен попадать в публичный репозиторий.

3.  **Запустите все сервисы с помощью Docker Compose:**
    Эта команда скачает образы, установит зависимости и запустит контейнеры в фоновом режиме.
    ```bash
    docker-compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
    ```

4.  **Примените миграции базы данных:**
    База данных запустилась, но она пустая. Выполните эту команду, чтобы создать все необходимые таблицы (например, `users`).
    ```bash
    docker-compose exec server flask db upgrade
    ```
    > Эту команду нужно выполнять один раз при первоначальной настройке проекта, а также каждый раз, когда вы подтягиваете из репозитория новые изменения в структуре БД (новые миграции).

5.  **Готово!**
    -   **Frontend** доступен по адресу: [http://localhost:3000](http://localhost:3000)
    -   **Backend API** доступен по адресу: [http://localhost:5000](http://localhost:5000)

## ⚙️ Работа с базой данных и миграциями

Когда вы изменяете модели в `server/app/models.py` (например, добавляете новое поле в таблицу `User`), необходимо создать файл миграции.

1.  **Создание новой миграции:**
    ```bash
    docker-compose exec server flask db migrate -m "Краткое описание изменений"
    ```
2.  **Применение миграции:**
    ```bash
    docker-compose exec server flask db upgrade
    ```
> **Важно:** Папка `server/migrations` **должна быть** в системе контроля версий (Git). Когда ваши коллеги скачают новую версию кода, они просто выполнят команду `flask db upgrade`, чтобы обновить свою локальную базу данных до актуального состояния.

## 📋 Основные команды Docker

-   **Запустить все сервисы (в фоне):** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml up -d`
-   **Остановить все сервисы:** `docker-compose down`
-   **Посмотреть логи (например, только сервера):** `docker-compose logs -f server`
-   **Выполнить команду внутри контейнера (например, миграцию):** `docker-compose exec server <команда>`
