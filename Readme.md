# CDEK: AI-инструмент для оценки выгорания сотрудников

Этот репозиторий содержит прототип AI-инструмента для хакатона от компании СДЭК. Приложение предназначено для ранней диагностики профессионального выгорания сотрудников, предоставления персональных рекомендаций и визуализации метрик в дашборде.

## 🤖 Технологический стек

-   **Frontend:** React, TypeScript
-   **Backend:** Python, Flask
-   **База данных:** PostgreSQL
-   **Оркестрация:** Docker, Docker Compose

2.  [**Git**](https://git-scm.com/downloads)

## 🚀 Запуск проекта (в режиме разработки)

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Breadstickhemmo/HAPPY_SDEK_SWAGA.git
    cd HAPPY_SDEK_SWAGA
    ```

2.  **Создайте файл с переменными окружения:**
    В корневой папке проекта создайте файл `.env`. Скопируйте в него содержимое ниже.
    ```
    # Конфигурация PostgreSQL
    DB_USER=sdek_user
    DB_PASSWORD=supersecret_password_123
    DB_NAME=sdek_hackathon_db
    DB_PORT=5432
    ```
    > **Важно:** Файл `.env` добавлен в `.gitignore` и не должен попадать в публичный репозиторий.

3.  **Запустите все сервисы с помощью Docker Compose:**
    Выполните команду в корневой папке проекта. Docker сам скачает все образы, установит зависимости и запустит контейнеры в режиме разработки с "горячей перезагрузкой".
    ```bash
    docker-compose -f docker-compose.yml -f docker-compose.dev.yml up --build
    ```

4.  **Готово!**
    -   **Frontend** будет доступен по адресу: [http://localhost:3000](http://localhost:3000)
    -   **Backend API** будет доступно по адресу: [http://localhost:5000](http://localhost:5000)
    -   **PostgreSQL** будет доступен на порту `5433` (или `5432`, см. ниже).

## 🔧 Устранение неполадок

### Не удается подключиться к базе данных через pgAdmin (или другой GUI-клиент)

**Симптом:** Вы получаете ошибку `FATAL: password authentication failed for user "sdek_user"`, хотя уверены, что пароль верный.

**Причина:** Это почти всегда означает, что на вашем компьютере уже запущен другой сервер PostgreSQL (установленный локально), который занимает стандартный порт `5432`. В этом случае Docker не может "пробросить" порт наружу, и ваш pgAdmin подключается к локальной базе, а не к базе в Docker.

**Решение:**

1.  Откройте файл `docker-compose.yml`.
2.  Найдите сервис `db` и измените порт:
    ```yaml
    # ...
    services:
      db:
        # ...
        ports:
          - "5433:5432" # <-- Измените 5432 на 5433
    # ...
    ```
3.  Полностью перезапустите Docker Compose (`down`, затем `up`).
4.  В настройках подключения pgAdmin укажите **Port: `5433`**. Теперь вы будете подключаться к базе данных внутри Docker-контейнера.

## 📁 Структура проекта

-   **/client**: React-приложение (Frontend).
-   **/server**: Flask-приложение (Backend), логика работы с AI-моделями и БД.
-   `docker-compose.yml`: Базовый файл конфигурации сервисов.
-   `docker-compose.dev.yml`: Дополнительные настройки для режима разработки.
-   `docker-compose.prod.yml`: Дополнительные настройки для продакшен-сборки.
-   `.env`: Локальный файл конфигурации (не отслеживается Git).
