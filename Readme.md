# CDEK: AI-инструмент для оценки выгорания сотрудников

Этот репозиторий содержит прототип AI-инструмента для хакатона от компании СДЭК. Приложение предназначено для ранней диагностики профессионального выгорания сотрудников, предоставления персональных рекомендаций и визуализации метрик в удобном дашборде.

## ✨ Ключевые возможности

-   **Аутентификация и роли:** Система регистрации и входа с разделением прав доступа для обычных сотрудников (`user`) и психологов (`psychologist`).
-   **Динамический конструктор тестов:** Психологи могут создавать как стандартные опросники (CBI, OLBI), так и полностью кастомизированные тесты с различными типами вопросов (шкала, выбор варианта, текстовый ответ).
-   **Интерактивное прохождение тестов:** Удобный пошаговый интерфейс "один вопрос за раз" для максимальной концентрации пользователя.
-   **Персональный дашборд "Мое состояние":**
    -   Динамический график для отслеживания уровня стресса во времени с фильтрацией (неделя, месяц, все время).
    -   Наглядные карточки с показателями стресса за сегодня и средним значением.
    -   Детальная таблица со всеми пройденными тестами.
-   **AI-рекомендации:** Интеграция с **GigaChat API** для генерации персонализированных советов на основе результатов тестов. Ответы форматируются в чистый текст без Markdown.
-   **Наполненная база данных:** Проект включает скрипт для автоматического заполнения БД десятками моковых пользователей с реалистичными данными (должности, стаж, KPI), предоставленными в рамках хакатона.

## 🚀 Запуск проекта (в режиме разработки)

1.  **Клонируйте репозиторий:**
    ```bash
    git clone [URL вашего репозитория]
    cd [название-папки-проекта]
    ```

2.  **Создайте файлы с переменными окружения:**

    **A) В корне проекта** создайте файл `.env` для бэкенда:
    ```env
    # Конфигурация PostgreSQL
    DB_USER=user
    DB_PASSWORD=password
    DB_NAME=sdek_db
    DB_PORT=5432

    # Секретный ключ для подписи JWT-токенов
    JWT_SECRET_KEY=your_super_secret_and_long_jwt_key_here

    # Учетные данные для GigaChat API
    GIGACHAT_CREDENTIALS=ВАШ_ДЛИННЫЙ_КЛЮЧ_ОТ_GIGACHAT_СЮДА
    ```

    **B) В папке `client`** создайте файл `.env` для фронтенда:
    ```env
    REACT_APP_API_BASE_URL=http://localhost:5000/api/v1
    REACT_APP_SERVER_URL=http://localhost:5000
    ```
    > **Важно:** Оба файла `.env` добавлены в `.gitignore` и не должны попадать в публичный репозиторий.

3.  **Запустите все сервисы с помощью Docker Compose:**
    Эта команда скачает образы, установит зависимости и запустит контейнеры в фоновом режиме.
    ```bash
    docker-compose up --build -d
    ```

4.  **(Только при первом запуске)** Примените миграции базы данных, чтобы создать все таблицы:
    ```bash
    docker-compose exec server flask db upgrade
    ```

5.  **(Только при первом запуске)** Заполните базу данных моковыми пользователями:
    ```bash
    docker-compose exec server flask seed-db
    ```
    Эта команда создаст несколько десятков пользователей на основе предоставленных данных. **Стандартный пароль для всех: `password123`**.

6.  **Готово!**
    -   **Frontend** доступен по адресу: [http://localhost:3000](http://localhost:3000)
    -   **Backend API** доступен по адресу: [http://localhost:5000](http://localhost:5000)

## ⚙️ Использование и ключевые сценарии

#### Вход в систему

Вы можете войти под любым из созданных пользователей. Например:
-   **Email:** `n.klyuchevskaya@sdek.ru`
-   **Email:** `l.zaretskaya@sdek.ru`
-   **Пароль (для всех):** `password123`

#### Получение роли психолога

Для доступа к функциям создания и редактирования тестов, пользователю необходима роль `psychologist`.

1.  Зарегистрируйте нового пользователя или используйте существующего.
2.  Выполните в терминале следующую команду, заменив email на нужный:
    ```bash
    docker-compose exec server flask set-role n.klyuchevskaya@sdek.ru psychologist
    ```
3.  Перезайдите в аккаунт на сайте, чтобы изменения вступили в силу. Теперь вам будет доступен конструктор тестов.

## 🗄️ Работа с базой данных и миграциями

Когда вы изменяете модели в `server/app/models.py` (например, добавляете новое поле), необходимо создать и применить файл миграции.

1.  **Создание новой миграции:**
    ```bash
    docker-compose exec server flask db migrate -m "Краткое описание изменений"
    ```
2.  **Применение миграции:**
    ```bash
    docker-compose exec server flask db upgrade
    ```
> **Важно:** Папка `server/migrations` **должна быть** в системе контроля версий (Git).

## 📋 Основные команды Docker

-   **Запустить/перезапустить все сервисы (в фоне):** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml up --build`
-   **Остановить все сервисы:** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml down`
-   **Остановить и удалить данные (полный сброс БД):** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml down -v`
-   **Посмотреть логи сервера:** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml logs -f server`
-   **Посмотреть логи клиента:** `docker-compose -f docker-compose.yml -f docker-compose.dev.yml logs -f client`
-   **Выполнить команду внутри контейнера:** `docker-compose exec <имя_сервиса> <команда>`
